How we could build it

The short answer: generate the beat with real-time synthesis inside the app, so every knob moves a real sound parameter with no delay, and use Claude as the music director that decides what an invented word should do. AI audio models are better used to make new samples ahead of time than to drive the beat live, because they answer in seconds, not milliseconds.

Where it runs

Best to perform on

iPad native

Swift with Apple's audio engine (or AudioKit), Metal for visuals.

  • Multi-touch: two knobs at once
  • Lowest latency, steady timing
  • MIDI controllers, Ableton Link
Same code, bigger rig

Mac native

One SwiftUI codebase builds iPad and Mac.

  • Audio interfaces, club mixers
  • Big screen for advanced sets
  • Keyboard shortcuts for cues
Best to start

Web app

Web Audio and WebGL, like this mockup.

  • Fastest to iterate and share by link
  • Solid in Chrome on Mac
  • iPad Safari works, less robust audio
Pro route

JUCE (C++)

Industry standard for audio software.

  • Can also ship as a plugin for Ableton
  • Mac, iPad, Windows
  • Slowest and costliest to build

Recommended path

  1. Prototype on the web (2–4 weeks). Grow this mockup into a proper engine and wire Claude in for invented controls. Lock the feel of knobs, cues and the 8-bar phrase grid while changes are cheap.
  2. iPad-first native app. Rebuild the engine in Swift for timing and touch; Mac comes from the same code. Add sample packs for drum quality.
  3. Advanced sets. Saved scenes, set planner with cue points across many phrases, AI-made samples, MIDI controller mapping, recording and export.
